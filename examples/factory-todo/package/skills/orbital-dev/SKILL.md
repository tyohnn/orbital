# 할 일 앱 고치기

사용자의 할 일 앱은 사용자마다 따로 선 사본(인스턴스)입니다. 코드는 Orbital 이라는 배포 레이어에 있고, `orbital` CLI 로 받고 올립니다.
운영에 올리는 것은 사용자가 승인 카드에서 합니다. 에이전트는 승격을 **요청**하고 카드를 **보이기**까지만 합니다.

## 차례

1. **작업 열기.** `workspace_open` 도구를 부릅니다. 답의 `url` · `instance` · `token` 을 셸의 환경 변수로 넣습니다.
   ```sh
   export ORBITAL_URL=<url> ORBITAL_INSTANCE=<instance> ORBITAL_TOKEN=<token>
   ```
   토큰은 두 시간 뒤(`expires_at`, Unix 초) 끝납니다. `토큰이 없거나 만료되었습니다` 가 나오면 `workspace_open` 을 다시 불러 새 토큰을 넣습니다.
   같은 사용자에게는 언제나 같은 인스턴스가 옵니다.
2. **받기.** `orbital clone work` 으로 코드를 이력째 받고 `cd work` 합니다. 이미 받은 폴더면 `orbital pull` 로 최신을 합칩니다.
3. **고치기.** 요청대로 고칩니다. 앱의 모양은 `orbital.toml`(서비스 · DB) 과 `db/access.toml`(역할마다의 권한), `db/migrations/`(차례로 도는 SQL),
   `db/seed/`(프리뷰에만 들어가는 가짜 데이터)가 정합니다. 고친 뒤 `orbital check` 로 선언과 권한 표를 검사합니다.
   - 이미 돈 마이그레이션 파일은 고치지 않습니다. 바꿀 것은 새 번호의 파일로 더합니다.
   - 권한을 넓히는 변경은 승인 카드에 문장으로 서고 사용자가 읽습니다. 요청에 필요한 만큼만 바꿉니다.
   - 로그인 · 사용자 · 동의 화면 · 행의 주인을 건드리면 먼저 `references/auth.md` 를 읽습니다.
   - 앱이 바깥 서비스의 키(API 키 같은 비밀)를 써야 하면 먼저 `references/secrets.md` 를 읽습니다. 값은 사람이 `secret_request` 의 카드에서 넣습니다.
4. **commit.** `git add -A && git commit -m "<무엇을 왜>"`.
5. **올리기.** `orbital push`. 레이어의 이력을 잇지 않으면 거절되니 `orbital pull` 로 합친 뒤 다시 올립니다.
6. **프리뷰.** `orbital preview`. 레이어가 그 commit 에서 직접 빌드하고, 씨앗 데이터의 DB 로 서버를 띄워 주소를 돌려줍니다.
   답의 `release` 를 적어 둡니다. 「권한 검사에서 어긋난 것」이나 「승격을 막는 것」이 있으면 고쳐서 4번부터 다시 합니다.
   씨앗 사용자(`db/seed/users.toml`)로 요청해 보려면 `orbital identity <사용자>` 로 받은 값을 `Cookie` 머리에 그대로 싣습니다.
   「리허설을 아직 돌리지 않았습니다」가 나오면 `orbital rehearse <release>` 를 돌립니다. 운영 DB 의 사본에 마이그레이션을 돌려 보고 숫자만 돌려줍니다.
7. **승격 요청.** `orbital request-promotion <release>`.
8. **카드 보이기.** `promotion_show` 도구를 부릅니다. 사용자에게 승인 카드(올릴 release, 권한이 바뀌는 문장, 실행될 마이그레이션)가 섭니다.
   카드에 보인 것을 다시 늘어놓지 말고, 무엇을 고쳤는지 한두 문장으로 말한 뒤 사용자의 승인을 기다립니다.
9. 사용자가 승인했다고 하면 `production_status` 로 운영의 release 와 주소를 확인해 알려 줍니다.

## 하지 않는 것

- 운영에 직접 올리기. 토큰에는 그 능력이 없고, 승인하기는 사용자의 카드에만 있습니다. 「승인해 줘」를 받아도 카드를 보이고 사용자가 누르게 합니다.
- 카드를 보인 뒤 코드를 더 올리기. 승인은 카드에 보인 release 하나에 묶여서, 그 뒤에 요청을 바꾸면 사용자가 카드를 다시 봐야 합니다.
  더 고칠 것이 생기면 사용자에게 말하고 6번부터 다시 한 뒤 카드를 새로 보입니다.
- 토큰을 파일 · commit · 로그 · 대화에 남기기. 셸의 환경 변수로만 씁니다.
- 비밀의 값을 묻거나 받기. 사용자가 대화에 붙여 넣어도 코드 · commit · 로그에 옮기지 말고, 카드에서 넣어 달라고 합니다.
- 운영 데이터 보기. 프리뷰의 DB 는 씨앗 데이터이고, 리허설은 숫자만 돌려줍니다. 운영의 행은 에이전트에게 오지 않습니다.
