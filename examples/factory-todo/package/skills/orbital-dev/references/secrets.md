# 비밀(API 키)

앱이 바깥 서비스의 키를 쓰면 그 값은 레이어의 금고에 있고, 앱은 같은 이름의 환경 변수로 받습니다. 에이전트는 이름만 다룹니다.
값을 묻지 않고, 코드 · commit · 로그 · 대화에 적지 않습니다.

## 차례

1. **선언.** `orbital.toml` 의 `[secrets] external` 에 이름을 적습니다. 이름은 대문자 · 숫자 · 밑줄이고 `ORBITAL_` 로 시작하지 않습니다.
   ```toml
   [secrets]
   external = ["BANK_API_KEY"]
   ```
   코드는 `process.env.BANK_API_KEY` 처럼 환경 변수로 읽습니다. 값이 없을 때(프리뷰에서 아직 넣지 않았을 때)도 앱이 뜨게 짭니다.
2. **프리뷰.** commit 하고 `git push origin main` → `preview`. 프리뷰가 선언을 읽어야 그 이름을 요청할 수 있습니다.
   프리뷰의 값이 아직 없으면 답의 `missing_secrets` 에 이름이 오고, 앱은 그 환경 변수 없이 섭니다.
3. **요청.** `secret_request` 도구에 이름과 까닭(무엇에 쓰는지, 500자 안)을 넘깁니다. 사용자에게 입력 카드가 섭니다.
   카드에는 운영과 프리뷰의 칸이 따로 있고, 값은 카드에서 레이어로 바로 갑니다(한 번 쓰는 입력 표는 주소가 아니라 머리말에 실립니다).
   에이전트와 팩토리는 값을 보지 못합니다.
   「선언하지 않았습니다」가 오면 1번과 2번을 마치고 다시 부릅니다.
4. **사람이 채움.** 사용자가 값을 넣었다고 할 때까지 기다립니다. 프리뷰의 값을 넣으면 프리뷰의 앱은 다음 요청부터 그 값으로 깹니다.
5. **승격.** `promotion_request` → `promotion_show`. 운영의 값이 없으면 「비밀 `…` 의 운영 값이 없습니다」로 거절됩니다.
   에이전트가 고칠 수 없는 일이니 사용자에게 카드의 운영 칸을 채워 달라고 합니다. 승인 카드에는 이번 변경으로 앱이 새로 받는 비밀의 이름이 섭니다.

## 알아 둘 것

- **프리뷰와 운영의 값은 따로입니다.** 운영의 값은 프리뷰에 가지 않고, 프리뷰의 값은 운영에 가지 않습니다. 프리뷰의 앱은 에이전트가 쓴 코드이고
  에이전트가 그 로그와 답을 읽으므로, 프리뷰에는 시험용 키를 넣게 합니다.
- 빌드와 마이그레이션에는 비밀이 오지 않습니다. 빌드 때 키가 필요한 코드로 짜지 않습니다.
- 값을 로그나 답에 찍는 코드를 쓰지 않습니다. 운영의 앱도 에이전트가 쓴 코드라, 값을 지키는 마지막 자리는 그 코드입니다.
- 지금 운영의 release 가 쓰는 비밀의 운영 값은 지울 수 없습니다. 이름을 바꾸려면 새 이름을 선언하고 요청한 뒤, 옛 이름을 뺀 release 를 올립니다.
