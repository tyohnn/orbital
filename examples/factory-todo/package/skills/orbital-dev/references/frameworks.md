# 프레임워크로 만든 앱(Next.js · NestJS · Vite)

앱이 `npm` 의 의존성을 쓰거나 프레임워크로 빌드하면 먼저 읽습니다. 레이어는 그 commit 에서 직접 빌드하고, 빌드와 서버를
환경을 비운 자리에서 돌립니다. 이 기계에서 되던 것이 레이어에서 막히는 자리를 모았습니다.

## 빌드

- **`package-lock.json` 을 commit 하고 빌드 명령은 `npm ci` 로 시작합니다.** `node_modules` 와 빌드 결과(`.next/`, `dist/`)는 commit 하지 않습니다.
  레이어는 에이전트가 올린 빌드 결과를 받지 않습니다.
- **빌드에는 비밀도 DB 도 없습니다.** 빌드가 받는 환경은 `PATH` · `HOME` 과 레이어가 정한 레지스트리 · 프록시의 설정뿐입니다.
  빌드할 때 DB 를 읽는 화면(미리 그리는 페이지)을 만들지 않습니다. Next.js 면 `headers()` 를 읽거나 `export const dynamic = "force-dynamic"` 으로
  요청마다 그리게 합니다.
- **의존성은 저장소에서 한 번 받습니다.** 서비스가 둘인 저장소(npm workspaces)는 최상위에 `[build] command = "npm ci"` 를 적습니다.
  이 명령이 서비스의 빌드보다 먼저 저장소 폴더에서 한 번 돌고(같은 환경 · 같은 제한 시간), 서비스의 `build` 는 `npm run build -w <이름>` 만 적습니다.
  `[build]` 가 실패하면 서비스의 빌드는 돌지 않고, 그 로그는 `preview_logs` 의 `build` 에 있습니다.
- 빌드가 실패하면 `preview` 의 답에 로그의 끝이 오고, `preview_logs` 로 더 봅니다. 레지스트리에 닿지 못한 실패(`ENOTFOUND`, `SELF_SIGNED_CERT_IN_CHAIN`)는
  에이전트가 고칠 수 없는 일입니다. 코드를 바꾸지 말고 사람에게 알립니다.

## 서버

- **포트는 `PORT`, 듣는 주소는 `127.0.0.1` 입니다.** 레이어가 `PORT` 와 `HOST` · `HOSTNAME`(모두 `127.0.0.1`)을 건넵니다.
  `next start` 는 둘 다 읽지 않고 모든 주소에서 들으니 `"start": "next start -H 127.0.0.1"` 로 적습니다(Next.js 의 `output: "standalone"` 서버는 `HOSTNAME` 을 읽는다고 문서에 적혀 있습니다. 레이어에서는 재지 않았습니다).
  NestJS 는 `app.listen(Number(process.env.PORT), process.env.HOST ?? "127.0.0.1")` 입니다.
- **경로의 머리는 잘리지 않습니다.** `path = "/api"` 인 서비스는 `/api/payslips` 를 그대로 받습니다. NestJS 는 `app.setGlobalPrefix("api")` 를 둡니다.
- **요청이 없으면 서버가 내려가고 첫 요청에 다시 뜹니다.** 메모리에 둔 것은 사라집니다. 뜨는 데 30초를 넘기면 그 요청은 실패합니다.
- **DB 는 `pg` 로 붙습니다.** 비밀번호 없이 `host: PGHOST`, `port: PGPORT`, `database: PGDATABASE`, `user` 자리에 업무 역할의 이름을 적습니다.
  요청마다 `BEGIN` → `SELECT set_config('orbital.identity', $1, true)`(신원 머리말 `x-orbital-identity` 를 그대로) → 질의 → `COMMIT` 입니다.
  업무 역할이 여럿이면 `orbital.me` 의 `roles` 를 읽고 그 사람에게 있는 역할로 붙습니다.

## 정적 서비스(Vite 같은 것)

- `output` 의 파일을 레이어가 그대로 내줍니다. `/` 와 `/` 로 끝나는 경로는 `index.html` 입니다.
- **화면 안의 경로(`/payslips/2026-11`)를 쓰면 서비스에 `fallback = "index.html"` 을 적습니다.** 파일이 없고 화면을 원하는 요청(`GET` + `Accept: text/html`)에만
  그 파일을 내줍니다. 확장자가 있는 경로(`/assets/app.js`, `/logo.png`)와 화면이 아닌 요청의 404 는 그대로라, 빠진 스크립트를 화면으로 덮지 않습니다.
  `fallback` 은 정적 서비스에만 적고, 빌드 결과의 폴더 안의 상대 경로입니다.

## 로그인과 프레임워크

- **로그인한 사람만 들어오는 서비스는 `auth = "required"` 와 `public` 을 함께 적습니다.** `public` 은 로그인 없이 내줄 경로의 머리 목록입니다.
  Next.js 는 `public = ["/_next/static"]`(로그인 화면의 스크립트와 글꼴)입니다. 로그인 화면(`[auth] login_path`)과 그 아래는 따로 적지 않아도 열립니다.
  - 공개 경로의 요청에는 **세션이 있어도 신원 머리말(`x-orbital-identity`)이 실리지 않습니다.** 사람마다 다른 답을 그 아래에 두지 않습니다.
  - 서비스의 `path` 아래의 평범한 경로만 적습니다(`..` · `%` · `//` · `;` 없이). 레이어의 경로(`/_orbital`, `/.well-known`)와 MCP 의 경로는 적지 못합니다.
  - 요청의 경로가 공개 경로처럼 보여도 풀어 보면 밖으로 나가는 모양(`/_next/static/..%2f..`)이면 공개로 보지 않습니다.
- 세션 없이 화면을 열면 레이어가 `login_path?next=…` 로 보내고(302), 화면이 아닌 요청은 401 입니다. 앱이 신원이 없을 때 따로 보낼 필요는 없지만, 두어도 됩니다.
- 화면의 로그인 함수(`sendLoginLink` · `me` · `logout`)는 아직 npm 에 없어 본보기처럼 `orbital-app.js` 를 앱 안에 넣어 둔 것을 씁니다.

## 일정

- **`[[schedule]]` 은 운영에서 그 시각에 레이어가 부릅니다.** cron 식은 다섯 칸(분 시 일 월 요일)이고 **UTC** 입니다. 한국 시각 오전 9시는 `0 0 * * *` 입니다.
  레이어는 그 서비스를 (자고 있으면 깨워) `POST <path>` 로 부르고, `x-orbital-schedule` 머리말에 그 일정을 가리키는 값을 싣습니다. 사람의 신원은 없습니다.
- **일정의 경로는 밖에서 부르지 못합니다.** 레이어가 밖에서 온 그 경로의 요청을 404 로 답하고, 밖에서 온 `x-orbital-` 머리말은 언제나 지웁니다.
  그래서 앱은 `x-orbital-schedule` 이 있으면 레이어가 부른 것으로 믿을 수 있습니다. 없으면 403 으로 답하게 둡니다.
- 프리뷰에서는 부르지 않고, 프리뷰에서도 그 경로는 밖에서 닿지 않습니다. 일의 몸은 따로 된 함수로 두어 그 함수를 시험합니다.
- 2xx 가 아닌 답 · 시간 초과(기본 10분)는 기록에 남고 **다시 부르지 않습니다.** 같은 일이 두 번 돌면 안 되는 일(급여)이 있어서입니다. 레이어가 내려가 있던
  동안 놓친 때는 몰아서 부르지 않고 한 번만 부릅니다. 결과는 사용자의 운영 상태(`production_status`)가 아니라 팩토리가 봅니다.
