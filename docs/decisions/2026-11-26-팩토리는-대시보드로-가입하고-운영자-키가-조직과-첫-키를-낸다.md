# 팩토리는 대시보드로 가입하고 운영자 키가 조직과 첫 키를 낸다

- 날짜: 2026-11-26
- 상태: 정함(사용자가 2026-11-26 에 정했다: 대시보드는 제품마다 그 제품의 모노레포에, 계정도 제품마다, Harmony OS 는 Orbital 의 고객이 아니다)
- 근거: `crates/orbital-server/tests/organizations.rs` 의 테스트 이름, `crates/orbital-core/src/keys.rs`

## 결정

Orbital 의 고객은 팩토리 제작자(팩토리를 만드는 개발사)이다. 그들이 Orbital 의 대시보드에 들어와 가입하고, API 키(service key)를 받아 가서
팩토리를 구성한다. 대시보드는 이 저장소 안의 앱(`apps/dashboard`)으로 서고, 계정은 Orbital 의 것이다. Higgs 와 계정을 나누지 않고,
Harmony OS 와 함께 쓰는 콘솔도 두지 않는다.

관리 서버(`orbitald`)에는 그 바닥을 둔다.

| 무엇 | 어떻게 |
|---|---|
| 조직을 만드는 길 | 운영자 키(`ORBITAL_ADMIN_KEY`)로 `POST /v1/admin/organizations`. 첫 키를 이 답에서 한 번만 보여 준다. 대시보드의 서버만 이 열쇠를 갖는다 |
| 키를 다루는 길 | 팩토리의 service key 로 `GET` · `POST /v1/keys`, `POST /v1/keys/{id}/revoke`. 제 조직의 키만 보이고, 다른 조직의 키는 없는 키와 같다 |
| 키를 두는 자리 | 레이어의 기록(`registry.json`)에 sha256 으로만. 비밀은 만든 답에서 한 번만 보인다 |
| 잠기지 않기 | 조직의 마지막 살아 있는 키는 폐기하지 못한다(core 의 `judge_revoke`, 속성 테스트) |
| 운영자의 손 | 살아 있는 키가 없는 조직에만 키를 내고(`…/keys`), 키를 모두 잃은 조직은 모든 키를 폐기하고 새 키 하나를 내어 되살린다(`…/reset-keys`) |
| 부트스트랩 | `ORBITAL_SERVICE_KEYS` 는 그대로 쓴다. 목록에 보이지 않고 API 로 폐기하지 못한다. 둘 가운데 하나는 있어야 뜬다 |

모양은 Higgs 의 조직 · 서비스 키(`crates/higgs-server/src/keys.rs`)와 같다. 두 제품을 쓰는 개발사가 같은 손버릇으로 쓴다.

## 왜

- **운영자 키로는 살아 있는 팩토리의 인스턴스에 닿지 못한다.** 대시보드가 털려도 운영자 키로 할 수 있는 일은 새 조직을 만들거나 잠긴 조직을
  되살리는 것뿐이다. 살아 있는 키가 있는 조직에는 키를 내지 않으므로, 운영자가 몰래 팩토리의 운영을 바꾸는 길이 없다.
- **사람과 로그인은 대시보드의 몫이다.** 관리 서버는 「이 열쇠가 어느 조직의 것인가」만 안다. 팀원 · 이메일 로그인 · 누가 키를 만들 수 있는지는
  대시보드가 정하고, 관리 서버의 판정(토큰 범위 · 승격)은 지금 그대로다.
- **환경 변수의 키를 지우지 않는다.** 이미 돌고 있는 팩토리(본보기 `factory-todo`, SDK 테스트)가 깨지지 않고, 대시보드가 없는 개발 환경도 그대로 뜬다.

## 아직 정하지 않은 것

- 대시보드(`apps/dashboard`)의 가입 · 이메일 로그인 · 팀원 · 키 화면. 테스트 이름을 먼저 확인받는다.
- 기록을 DB 로 옮길 때 키도 함께 옮긴다(지금은 파일 하나라 관리 서버를 하나만 띄운다).
