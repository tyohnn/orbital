# PostgreSQL 은 가장 높은 버전을 쓴다

- 날짜: 2026-11-25
- 상태: 정했다(사람의 결정)

## 결정

PostgreSQL 의 가장 높은 주 버전을 쓴다. 지금은 19 이고(19.0 이 2026-11-19 에 나왔다), `scripts/pg-local.sh` 와 CI 가 설치된 것 가운데
가장 높은 버전을 띄운다. 18 보다 낮으면 멈춘다.

## 왜

- **database 복제가 18 부터 있다.** `file_copy_method = clone` 과 `CREATE DATABASE … STRATEGY = FILE_COPY` 로 운영 DB 의 사본을 뜨고,
  예행연습과 승격 직전의 되돌릴 지점에 쓴다.
- **멤버십마다 `SET` 을 끄는 것이 16 부터 있다.** 로그인이 다른 역할로 바꿔 타지 못하게 하는 데 쓴다.

## 실제로 본 것(2026-11-25, 이 저장소의 개발 환경)

- PostgreSQL 19.0 을 공식 패키지 저장소에서 설치해 띄웠다. `file_copy_method = clone` 을 받는다.
- 392MB database 의 복제가 `FILE_COPY` 로 0.54초, `WAL_LOG` 로 0.88초였다. 파일시스템이 ext4 라서 블록을 나눠 쓰는 복제(reflink)는 아니다.
  XFS 에서의 숫자는 기획안 11절의 0번에서 잰다.
- 원본에 다른 연결이 있으면 복제는 바로 실패하지 않고 그 연결이 끝나기를 몇 초 기다린다(4초짜리 질의가 도는 동안 시작한 복제가 성공했다).

## 조심할 것

- 19.0 은 나온 지 엿새다. 실제 고객의 데이터를 받기 전까지 작은 버전이 몇 번 더 나온다. 그때의 가장 높은 작은 버전으로 올린다.
- 백업 도구(pgBackRest)와 확장이 19 를 받는지는 확인하지 않았다. 백업과 복구 훈련(기획안 11절의 8번)에서 본다.
