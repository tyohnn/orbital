# 팩토리는 시작 템플릿을 복사해 제 앱과 가격만 채운다

- 날짜: 2026-11-26
- 상태: 제안(구현하며 정했다. 사람의 확인이 남았다. 특히 「계정 · 로그인 · 결제를 넣지 않고 자리만 둔다」와 아래 「테스트 이름」의 목록)
- 근거: `templates/factory-starter/`, `scripts/new-factory.mjs`, `templates/test/*.test.ts`, `templates/factory-starter/server/test/*.test.ts`
- 기획의 문장: 「스캐폴드, 플러그인, 팩토리의 서버가 한 번에 나온다. 팩토리는 제 앱과 가격만 채운다. 지금의 `examples/factory-todo` 가 씨앗이다」
- DX 의 기준: 「처음 10분에 인스턴스 하나가 서는가」

## 결정

1. **템플릿은 저장소 하나의 모양이다**(`templates/factory-starter/`). 팩토리 개발자는 통째로 복사해 제 것으로 고친다. 셋이 한 번에 들어 있다.
   - `scaffold/`: 고객마다 복사될 앱. `examples/todo-next` 를 본으로 한 가장 작은 Next.js 앱(메모 하나)과 선언 · 권한 표 · 마이그레이션 · 씨앗 · 적합성 테스트.
     바꿀 자리는 파일 안에 ✏️ 로 표시한다.
   - `plugin/`: 에이전트 플랫폼에 올리는 얇은 것(MCP 서버 하나의 주소와 스킬 `app-dev`). 훅도 설치할 명령도 없다.
   - `server/`: 플러그인의 도구가 닿는 팩토리의 서버. `examples/factory-todo` 의 서버를 씨앗으로, SDK 가 주는 것을 제자리에 쓴다.
2. **만드는 길은 복사 스크립트다**(`node scripts/new-factory.mjs <폴더> <이름>`). 템플릿을 새 폴더로 복사하고(`node_modules` · `.factory` · 묶은 tarball 은 빼고),
   이름(플러그인 · MCP 서버 · 서버 패키지 · 레이어의 앱)을 바꾸고, 저장소의 SDK 를 `npm pack` 해 `vendor/` 에 두고 서버가 그 tarball 을 `file:` 로 문다.
   `npm create` 는 SDK 를 npm 에 올린 뒤에 한다. 그때 바뀌는 것은 서버의 `package.json` 한 줄(`"@harmony/orbital": "^0.1.0"`)이다.
3. **저장소 안에서는 템플릿의 서버를 워크스페이스로 두지 않는다.** 복사본이 쓰는 `package.json` · `tsconfig.json` 에 저장소에서만 쓰는 조건(`orbital-source`)을
   넣지 않기 위해서다. 저장소의 게이트는 루트의 스크립트가 그 조건을 붙여 타입 검사(`tsc -p templates`)와 테스트를 돌리고, 의존은 루트의 `node_modules` 에서 찾는다.
4. **웹훅을 받는 길**(`POST /webhooks/orbital`)은 받은 날것의 본문으로 `verifyWebhook` 을 부르고, `id` 로 겹침을 거르고, 종류마다 「여기서 고객에게 알린다」의
   자리(`server/src/notify.ts`)를 부른다. 처리기가 실패하면 500 으로 답하고 처리한 것으로 적지 않아 레이어가 다시 보낸다. 웹훅을 걸지 못하는 곳(로컬)에서는
   `events.list` 로 물어보는 고리가 **같은 처리기**를 부른다. 처리한 자리(마지막 id)는 팩토리의 폴더(`FACTORY_HOME/inbox.json`)에 두어 다시 떠도 다시 알리지 않는다.
   한 조직의 이벤트는 id 의 차례로 오므로 「처리한 마지막 id」 하나로 겹침을 거른다. 웹훅을 받으면 받은 것 앞에 받지 못한 이벤트(웹훅을 걸기 전의 것, 레이어가 하루 동안 보내다 그만둔 것)를 목록에서 차례로 이어 받아 먼저 처리한다.
   이어 받지 못하면 받은 것도 처리하지 않고 500 으로 답한다(받은 것만 처리하면 처리한 자리가 넘어가 앞의 것을 영영 건너뛴다). 웹훅의 비밀은 환경 변수(`ORBITAL_WEBHOOK_SECRET`)에만 두고, 있으면 웹훅을 받고 없으면 물어본다.
5. **승인 카드**는 기다리는 release · 권한이 바뀌는 문장 · 실행될 마이그레이션 · 리허설의 숫자 · 이번에 새로 받는 비밀과 그 운영 값이 있는지를 보이고,
   사람이 누르면 `releases.promote` 를 부르며 `approver` 에 고객의 계정 식별자를 싣는다(이력에 남는 이름표). 리허설의 숫자는 레이어의 기다리는 요청에 없어서,
   에이전트가 `rehearse` 를 부를 때 팩토리의 서버가 (인스턴스, release)마다 메모리에 둔다. 리허설은 운영이 있고 돌 마이그레이션이 있을 때만 필요하다
   (처음 오르는 것은 운영 DB 가 없다). 리허설이 필요한데 통과하지 않았거나 새 비밀의 운영 값이 없으면 승인 단추를 세우지 않는다. 레이어도 막지만 누르기 전에 보이는 편이 낫다.
6. **고객 계정과 인스턴스를 잇는 자리**는 인터페이스 하나(`Accounts`: 이 고객의 인스턴스 · 이 인스턴스의 고객)와 메모리 구현 하나다. **가입 · 로그인 · 결제는 넣지 않는다.**
   플랫폼이 연결하려면 OAuth 가 있어야 해서 본보기의 「계정 이름을 적는 칸」을 개발용 연결로 옮겼고, 서버는 그 연결로 바깥(loopback 이 아닌) 주소에서 뜨지 않는다.
   가격과 결제를 붙일 자리는 `Accounts.instanceFor` 의 주석(인스턴스를 세우기 전에 결제를 확인한다)이다.
7. **열쇠는 환경 변수에서만 읽는다.** service key 와 웹훅의 비밀은 SDK 와 확인 함수에 한 번 건네고 로그 · 도구의 답 · 오류에 싣지 않는다.
   운영의 로그 · 함대 · 이력은 운영자의 스크립트(`npm run operator -- …`)가 읽고 도구로 돌려주지 않는다.
8. **`examples/factory-todo` 는 그대로 둔다.** 템플릿과 겹치는 코드(git 이어 주기 · 작업 · 카드 · 패키지 짓기)가 있지만 본보기의 테스트 28개가 게이트에 있고
   본보기는 「팩토리 하나가 실제로 어떻게 생겼나」를 보이는 자리라 이번에는 겹쳐 둔다. 나중에 본보기를 템플릿의 인스턴스(복사본)로 바꿀 수 있다.

## 테스트 이름(계약)

**게이트**(`npm run test:starter`, `pr:check` 에 든다). 템플릿 안의 테스트는 복사본에도 따라가 팩토리가 계속 돌린다.

`templates/factory-starter/server/test/webhook.test.ts`
- 서명이 맞는 웹훅은 처리기를 한 번 부르고 200 으로 답한다
- 서명이 틀리면 401 로 거절하고 처리기를 부르지 않는다
- 서명의 때가 5분보다 멀면 거절한다 — 되풀이 막기
- 같은 id 를 두 번 받으면 겹쳐 와도 처리기는 한 번만 돈다
- 서명은 받은 날것의 본문으로 확인한다 — JSON 을 읽어 다시 쓴 본문이 아니다
- 처리기가 실패하면 500 으로 답하고 처리한 것으로 적지 않는다 — 레이어가 다시 보내면 처리한다
- 물어보는 고리는 events.list 를 차례로 이어 받아 같은 처리기를 부르고 처리한 id 는 건너뛴다
- 웹훅을 받으면 그 앞에 받지 못한 이벤트부터 목록에서 이어 받아 차례대로 처리한다
- 앞의 것을 이어 받지 못하면 받은 웹훅도 처리하지 않고 500 으로 답한다 — 처리한 자리가 앞의 것을 건너뛰지 않는다
- 처리한 자리는 팩토리의 폴더에 남아 다시 떠도 처리한 이벤트를 다시 알리지 않는다
- 웹훅의 답과 팩토리의 로그에 웹훅의 비밀이 실리지 않는다

`templates/factory-starter/server/test/accounts.test.ts`
- 같은 고객의 요청이 겹쳐 와도 인스턴스는 하나만 선다
- 인스턴스로 고객을 찾는다 — 웹훅을 받은 쪽이 누구에게 알릴지 안다

`templates/factory-starter/server/test/card.test.ts`
- 승인 카드는 권한이 바뀌는 문장 · 마이그레이션 · 리허설의 숫자 · 운영의 값이 없는 비밀을 보인다
- 리허설이 필요한데 돌리지 않았으면 카드가 그렇다고 말하고 승인 단추를 세우지 않는다
- 에이전트가 지은 글은 카드에서 이스케이프된다

`templates/factory-starter/server/test/main.test.ts`
- service key 가 없으면 뜨지 않고 무엇을 넣을지 말한다
- 개발용 연결로는 바깥 주소에서 뜨지 않는다 — 운영에 내기 전에 로그인을 붙인다
- 레이어가 거절해 뜨지 못해도 service key 는 오류와 로그에 실리지 않는다

`templates/factory-starter/server/test/plugin.test.ts`
- 플러그인은 MCP 서버 하나와 스킬 하나를 묶고 훅이 없다 — 스킬이 부르라는 도구는 모델이 부를 수 있는 도구다
- 플러그인의 묶음과 스킬에는 레이어를 직접 부르라는 말이 없다

`templates/test/new-factory.test.ts`(저장소에만 있다)
- 템플릿을 새 폴더로 복사하고 플러그인 · MCP 서버 · 서버 패키지 · 앱의 이름을 바꾼다
- 복사본의 서버는 저장소의 SDK 를 npm pack 한 tarball 로 문다
- node_modules · .factory · 묶은 tarball 은 복사하지 않는다
- 이름이 틀리거나 폴더가 비어 있지 않으면 아무것도 쓰지 않고 무엇을 고칠지 말한다
- 스캐폴드에 실린 orbital-app.js 는 SDK 의 app.ts 에서 타입만 걷은 것과 같다
- 스캐폴드의 선언과 권한 표는 orbital check 를 통과한다

**무거운 묶음**(`npm run test:frameworks` 의 뒤, `templates/test/lap.test.ts`). 레지스트리에서 받고 Next.js 를 빌드해 느리다.
- 복사한 템플릿이 README 의 명령대로 설치되고 타입 검사와 자기 테스트를 통과한다
- 팩토리를 띄우고 `npm run try` 를 부르면 스캐폴드를 올리고 인스턴스를 세워 프리뷰가 선다 — 처음 10분
- 에이전트가 도구와 git 만으로 고쳐 올리고 승격을 요청하면 승인 카드의 길로 고객의 승인으로 오르고 이력에 고객의 이름표가 남는다
- 마이그레이션과 밖에서 넣는 비밀을 더한 release 의 승인 카드는 리허설의 숫자와 새 비밀을 보인다
- 웹훅이 promotion.succeeded 를 한 번만 처리한다 — 같은 이벤트를 다시 보내도
- 운영자의 스크립트가 함대 · 이력 · 서비스의 상태를 읽는다
- 도구의 답과 팩토리의 로그에 레이어의 주소 · 토큰 · service key · 웹훅의 비밀이 없다

## 왜

- **10분 안에 서려면 고칠 자리가 한눈에 보여야 한다.** 본보기는 「할 일 카드 공방」이라는 팩토리 하나라 무엇이 팩토리의 것이고 무엇이 틀인지 갈리지 않는다.
  템플릿은 바꿀 자리를 표(README)와 ✏️ 로 가리키고, 나머지(작업 · git 이어 주기 · 카드 · 웹훅)는 고치지 않아도 도는 틀로 둔다.
- **계정과 결제는 팩토리마다 다르고 아직 사람이 정하지 않았다.** 템플릿이 넣으면 팩토리가 그것을 걷어 내는 일이 생긴다. 자리(인터페이스와 주석)만 두고,
  개발용 연결이 운영으로 새지 않게 바깥 주소에서는 뜨지 않게 했다.
- **웹훅과 물어보기를 한 처리기로 모은다.** 로컬에서는 레이어가 팩토리에 닿지 못해 웹훅을 시험할 수 없다. 처리기가 하나면 로컬에서 본 것이 운영에서도 같다.

## 값

- 고객과 인스턴스의 짝이 메모리에 있어 팩토리가 다시 뜨면 같은 고객이 새 인스턴스를 받는다. 시험용 조직은 인스턴스가 10개까지라 개발 중에 자주 다시 띄우면
  상한에 닿는다. README 가 운영자의 스크립트로 함대를 보고 걷는 길을 적는다. 실제 팩토리는 `Accounts` 를 제 DB 로 바꾼다.
- 승인의 표 · 리허설의 숫자 · 연결의 토큰 · 열린 작업도 메모리에만 있다(본보기와 같다).
- 템플릿의 스캐폴드는 Next.js 라 프리뷰 한 번에 레지스트리에서 받고 빌드한다(이 기계에서 15초 안팎). 레이어가 프록시 뒤에 있으면 운영자가 `ORBITAL_BUILD_ENV` 를 줘야 한다.

## 아직 정하지 않은 것

- 가입 · 로그인 · 결제(가격표, 무료 체험, 인스턴스를 세우기 전의 결제 확인). 붙일 자리만 있다.
- SDK 를 npm 에 올리고 `npm create` 로 만드는 길. 승인 카드와 웹훅 처리기를 SDK 의 부품으로 내는 일.
- 본보기(`examples/factory-todo`)를 템플릿의 복사본으로 바꾸는 일.
