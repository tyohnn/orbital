# 독립 제품으로 세우고 기계만 빌린다

- 날짜: 2026-11-25
- 상태: 정했다(사람의 결정)
- 근거: [Orbital 기획안](https://claude.ai/artifact/R9fEaCArNwVN1aWt9WPdzY) 1절 · 8절 · 13절

## 결정

Orbital 을 Harmony OS 나 Higgs 의 저장소 안이 아니라 독립 저장소와 독립 서비스로 만든다. 빌리는 것은 VM · 디스크 · object storage ·
네트워크 같은 기계뿐이고, 관리 서버 · 빌더 · router · Postgres 관리 · DB proxy 는 우리 코드로 짓는다. Vercel 같은 배포 플랫폼 위에 얹지 않는다.

## 왜

- **잇는 층은 어차피 우리 것이다.** 미리보기까지만 되는 토큰, 사람의 승인, 포크 전체에 올리기는 조사한 모든 플랫폼에서 덧붙여야 하는 일이었다.
- **차별점이 서버와 DB 사이에 있다.** 업무 역할마다 다른 로그인, 서명된 신원, 데이터를 보이지 않는 예행연습은 그 사이의 proxy 와 Postgres 운영에서 나온다.
- **배포 플랫폼을 밑에 두면 관리하기 어렵다.** 모든 팩토리의 비용이 우리 계정 하나로 묶여 오고, 값의 단위와 한도를 그쪽이 정하며, 마진이 한 겹 더 쌓인다.
  쓰는 양은 우리 부품(router · proxy · 빌더)이 직접 잰다.

## 그래서 지키는 것

- Orbital 은 host(팩토리)와 에이전트 플랫폼의 코드 · 표 · 용어를 가져오지 않는다. 누가 무엇을 할 수 있는지는 host 가 정해 토큰으로 넘긴다.
- 서버 실행기는 갈아 끼울 수 있는 자리로 둔다. 직접 지은 실행기, AWS Lambda, Cloud Run 을 같은 자리에서 잰 뒤 정한다(기획안 11절의 0번).

## 아직 정하지 않은 것

- 서버 실행기를 직접 지을지. 0번 확인의 숫자를 보고 정한다.
- 클라우드. AWS 서울을 제안해 두었다.
