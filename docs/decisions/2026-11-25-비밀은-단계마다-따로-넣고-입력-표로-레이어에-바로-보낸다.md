# 비밀은 단계마다 따로 넣고 입력 표로 레이어에 바로 보낸다

- 날짜: 2026-11-25
- 상태: 정함(기획안 11절의 6번 「비밀 입력 카드와 금고」)
- 근거: `crates/orbital-server/tests/secrets.rs` 와 `crates/orbital-core/src/secrets.rs` 의 테스트 이름

## 결정

앱이 바깥 서비스의 키를 쓰면, 선언에는 이름만 적고(`[secrets] external`) 값은 사람이 넣는다. 끝 기준은 **에이전트가 비밀의 값을 한 번도 보지 않고 운영에 오른다**이다.

| 무엇 | 어떻게 |
|---|---|
| 값의 자리 | 인스턴스와 단계(프리뷰 · 운영)마다 따로. 두 칸은 서로 넘어가지 않고, 한쪽이 없다고 다른 쪽으로 대신하지 않는다 |
| 금고 | `ORBITAL_HOME/vault.json`(0600)에 봉인한 글로만 둔다. 봉인에는 `orbital/secrets/v1`, 조직, 인스턴스, 단계, 이름을 묶는다. 열쇠는 `ORBITAL_SEAL_KEY` 이고, 없으면 값을 넣지 못한다 |
| 들어오는 길 | service key 로 바로 넣기(`PUT /v1/instances/{id}/secrets/{name}`), 그리고 입력 표(`POST …/entries` → `{url, ticket, expires_at}` → 사람의 브라우저가 고정된 주소 `POST /v1/secret-entries` 에 `Authorization: Bearer <표>` 를 실어 보냄) |
| 나가는 길 | 앱의 서버 서비스의 환경 변수 하나. 값을 읽는 API 는 어떤 열쇠로도 없다. 목록은 이름 · 선언 여부 · 요청 · 단계마다 채워졌는지와 그 때만 돌려준다 |
| 요청 | 에이전트의 토큰(`secrets_request`)이나 service key 로 이름과 까닭만 적는다. 그 인스턴스의 release 가 밖에서 넣는다고 선언한 이름만 받는다 |
| 승격 | 운영의 칸이 하나라도 비면 막는다(`Blocker::SecretMissing`). 되돌리기와 관리 서버가 다시 뜰 때도 같은 판정을 지나, 값 없이 운영을 세우지 않는다 |
| 빌드와 마이그레이션 | 비밀을 건네지 않는다 |
| 값을 바꾸면 | 그 단계에 도는 서버 서비스를 재워, 다음 요청이 새 값으로 깬다. 지금 운영의 release 가 쓰는 비밀의 운영 값은 지우지 못한다 |
| 승인 카드 | 이번 변경으로 앱이 새로 받게 되는 비밀의 이름을 싣는다(`new_secrets`) |

## 왜

- **단계를 가르는 까닭: 프리뷰의 값은 에이전트가 본다.** 프리뷰의 앱은 에이전트가 쓴 코드이고, 에이전트는 그 로그와 답을 읽는다.
  `console.log(process.env.BANK_API_KEY)` 한 줄이면 값이 에이전트에게 간다. 운영의 값을 프리뷰에 건네면 끝 기준이 깨진다.
  그래서 프리뷰에는 시험용 키를 따로 넣게 하고, 카드가 그것을 알린다. 프리뷰의 값이 운영으로 가지 않는 것도 같은 까닭이다. 에이전트가 본 값이 운영을 돌리면 안 된다.
- **입력 표인 까닭: 값이 팩토리와 플랫폼의 기록을 지나지 않게 한다.** 사람이 값을 도구의 인자로 넣으면 에이전트 플랫폼의 도구 호출 기록에 남고,
  팩토리의 서버가 받아 넘기면 팩토리의 로그와 메모리를 지난다. 입력 표는 레이어가 낸 한 번 쓰는 주소이고, 사람의 브라우저(팩토리의 카드)가 그 주소로
  레이어에 바로 보낸다. 표를 내는 팩토리의 도구는 화면 전용이라 모델의 도구 목록에 없고, 표가 든 주소는 화면에만 가는 `_meta` 에 실린다.
- **표는 묶고 짧게 둔다.** 인스턴스 · 이름 · 단계 하나에 묶여 본문이 다른 자리를 적으면 거절한다. 10분 안에 한 번 쓰고, 기록에는 sha256 만 둔다.
  이 길은 쿠키도 키도 보지 않고 표만 보므로, 다른 출처의 브라우저에 CORS 를 열어도(`Access-Control-Allow-Origin: *`, 자격 증명 없이) 얻는 것이 없다.
- **판정은 core 에 둔다.** 빠진 이름, 값의 한도(비어 있지 않음 · 64 KiB · NUL 없음), 입력 표의 판정(이미 씀 · 만료 · 다른 자리), 요청할 수 있는 이름은
  순수한 함수라 예시 · 속성 테스트로 잰다. 난수 · 시계 · 봉인 · 파일은 관리 서버에 둔다.

## 알려진 한계

- **운영의 앱도 에이전트가 쓴 코드다.** 승인된 코드가 값을 밖으로 보내거나 답에 실을 수 있다. 막는 것은 사람의 승인(승인 카드가 새로 받는 비밀의 이름을 보인다)과
  나중의 밖으로 나가는 네트워크 제한(egress)이다. 레이어는 값이 레이어의 답 · 로그 · 기록에 실리지 않는 것까지만 지킨다.
- **표를 가로챈 쪽이 10분 안에 틀린 값을 넣을 수 있다.** 표는 한 번만 쓰이므로 사람은 「이미 쓴 표」를 보고 알아챈다. 값을 읽어 가지는 못한다.
- **금고가 아직 파일이다.** 레이어의 기록과 같은 폴더에 있고, 서버가 하나일 때의 모양이다. 열쇠는 새 열쇠와 옛 열쇠(`ORBITAL_SEAL_KEY_PREVIOUS`)를
  함께 주고 한 번 띄워 다시 봉인한다([런북](../runbook/봉인의-열쇠-바꾸기.md)). 어느 열쇠로도 풀리지 않는 줄은 사람이 다시 넣어야 한다.
- **표는 주소가 아니라 머리말로 간다(2026-11-26).** 처음에는 표를 주소의 경로에 실었는데, 레이어 앞의 프록시와 부하 분산기는 요청의 경로를 접근 기록에
  남긴다. 그 기록을 읽을 수 있는 쪽이 10분 안에 틀린 값을 넣을 수 있었다. 이제 주소는 고정이고 표는 `Authorization: Bearer` 로만 가며, CORS 의 사전 요청이
  그 머리말을 받는다. 그래도 카드가 도는 플랫폼의 화면 기록과 브라우저의 확장은 표를 볼 수 있다.
- 값을 바꾸는 순간 깨우는 중이던 프로세스는 바뀌기 전의 값을 읽었을 수 있다. 그 프로세스는 첫 요청이 끝나면 재운다.

## 아직 정하지 않은 것

- 값의 만료 · 돌려 바꾸기 알림, 여러 인스턴스에 같은 값을 넣기, 정적 서비스에 비밀을 건네기(지금은 건네지 않는다).
- 요청을 거두는 길. 지금은 마지막 요청이 남고 인스턴스를 지울 때 함께 지운다.
