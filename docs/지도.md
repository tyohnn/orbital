## 선언과 권한 표

- **되는 것.** 선언 파일의 타입(`Manifest`)과 검증(`Manifest::check`): 서비스(서버 · 정적), 일정, database(스키마 · 업무 역할), 비밀(만드는 것 · 넣는 것).
  값을 적을 자리가 없고 모르는 칸은 읽지 않습니다. 권한 표의 타입(`Access`)과 검증: 다섯 가지 말(none · read · read own · read write · read write own),
  표마다 모든 역할을 적어야 하고, 행 단위 규칙을 끄려면 까닭을 적어야 합니다. 문제는 찾은 것을 모두 돌려줍니다.
  CLI(`orbital check` · `plan` · `diff`)가 폴더의 두 파일을 읽어 검사하고, 세워질 SQL 과 권한 변화의 문장을 보입니다.
  본보기는 `examples/` 에 둘 있습니다(NestJS + Vite, Next.js 풀스택).
- **남은 일.** 업무 역할과 표에 사람이 읽는 이름을 붙이기(승인 카드의 문장에 `manager` 대신 「팀장」). 밖으로 나가는 네트워크의 선언.

## 역할과 권한

- **되는 것.** 역할 계획(`provision` · `grants`): 소유자, 마이그레이션, 업무 역할의 묶음, (서비스, 업무 역할)마다의 로그인. 권한은 먼저 모두 걷고 권한 표에 적힌 것만 줍니다.
  권한 검사(`check::judge`): 실제 DB 의 모습이 선언과 권한 표에 정확히 같은지 봅니다(모자라도 남아도 실패). 권한 변화의 문장(`describe::changes`).
  속성 테스트가 「어떤 선언이든 계획대로 세운 DB 는 검사를 통과한다」와 「권한을 하나라도 더하면 실패한다」를 잽니다.
  `orbital-pg` 가 계획을 실제 PostgreSQL 에 세우고(`provision` · `migrate` · `grant`), 실제 DB 의 모습을 읽어(`snapshot`) 검사에 넘깁니다.
  실제 DB 의 테스트가 「다른 역할로 바꿔 타지 못한다」, 「표를 만들거나 고치지 못한다」, 「다른 인스턴스의 database 에 접속하지 못한다」,
  「마이그레이션이 선언에 없는 스키마를 만들지 못한다」를 그 역할로 접속해 해 보는 것으로 잽니다.
- **남은 일.** 씨앗 데이터에서 역할마다 실제로 읽어 「자기 행만」을 재기(권한 검사의 한 항목으로). 선언에서 뺀 역할을 걷는 단계(`stale_roles` 는 찾기만 합니다).
  함수 · 뷰 · 열 단위의 권한. 어떤 마이그레이션이 이미 돌았는지의 기록.
- **결정.** [로그인은 서비스와 업무 역할마다 두고 비밀번호를 두지 않는다](decisions/2026-11-25-로그인은-서비스와-업무-역할마다-두고-비밀번호를-두지-않는다.md)

## 토큰

- **되는 것.** 범위 판정(`scope::judge`): 조직과 인스턴스가 다르면 없는 것으로 답하고, 만료 시각부터 거절하고, 능력에 없는 일은 거절합니다.
  운영을 바꾸는 능력은 타입에 없어서 적어 보내도 읽히지 않습니다. 속성 테스트 넷.
- **남은 일.** service key 를 조직마다 내고 거두는 길(지금은 서버의 설정에 적습니다). 토큰을 만료 전에 거두기.

## 승격

- **되는 것.** 승격의 규칙(`release::promote`): 레이어가 빌드했고, 권한 검사를 통과했고, 예행연습이 통과한(또는 필요 없는) release 만 오릅니다.
  승인은 release 의 식별자 하나에 묶여서, 승인한 뒤 commit 이 더해지면 그 승인으로는 올리지 못합니다. 고객의 요청과 기능 업데이트는 고객이,
  보안 · 법 · 핵심 패키지의 변경은 팩토리가 승인합니다. 승격 뒤 상태 확인에 실패하면 코드를 앞의 release 로 돌리고,
  되돌리면 데이터를 잃는 마이그레이션이면 기계가 정하지 않고 사람에게 묻습니다(`after_promotion`).
- **남은 일.** 마이그레이션이 더하기만 하는지 가리기(지금은 하나라도 돌았으면 「되돌리면 데이터를 잃는다」로 봅니다). rollout(여러 인스턴스에 차례로).

## DB 연결

- **되는 것.** proxy(`orbital-proxy`): 듣는 자리 하나가 서비스 하나이고, 서비스가 비밀번호 없이 업무 역할의 이름만으로 붙으면 그 서비스의 로그인으로 DB 에 대신 들어갑니다.
  선언에 없는 역할은 거절하고, database 는 인스턴스의 것으로 바꾸고, 역할을 바꾸거나 복제 연결을 여는 시작 설정은 버립니다. 질의 취소도 지나갑니다.
  서명된 신원(`orbital-pg::identity`): router 가 세션을 확인해 서명한 신원을 앱이 트랜잭션마다 싣고, DB 안의 `orbital.subject()` 가 읽을 때마다 서명 · 인스턴스 · 만료를 확인합니다.
  `orbital.role()` 은 연결의 업무 역할을 돌려줘, 마이그레이션이 인스턴스의 식별자를 몰라도 행 단위 규칙에서 역할을 가릅니다.
- **남은 일.** 연결 모아 쓰기. proxy 와 DB 사이를 인증서로 믿기(지금은 닿는 자리를 막는 것에 기댑니다). 서명의 열쇠 바꾸기(옛 열쇠와 새 열쇠를 함께 받는 기간).
  앱이 신원을 싣는 SDK(`db.as`). 신원에 업무 역할을 싣는 형식(`v2`).

## 로그인

- **되는 것.** router(`orbital-router`): 미리보기와 운영마다 하나가 포트 하나를 듣고, 레이어가 알리는 서비스의 주소는 router 의 주소 + 서비스의 `path` 입니다.
  요청은 `path` 가 가장 길게 맞는 서비스로 갑니다(`auth::route`). 서버 서비스에는 흘려보내고(앱으로 가는 연결은 살려 둡니다), 정적 서비스는
  빌드 결과의 폴더에서 파일을 내주되 폴더 밖(`..`, 풀어 쓴 `%2e%2e`, 폴더 밖을 가리키는 심볼릭 링크, `.` 으로 시작하는 파일)은 내주지 않습니다.
  **신원이 앱에 닿는 길은 하나입니다.** 밖에서 온 `x-orbital-` 머리말은 `[auth]` 가 있든 없든 언제나 지우고, 세션 쿠키를 확인했을 때만
  60초짜리 서명된 신원을 `x-orbital-identity` 에 붙입니다. 레이어의 쿠키(`__Host-orbital-*`)는 앱에 넘기지 않고, 앱이 그 이름으로 심지도 못합니다.
  사용자 · 초대 · 링크 · 세션은 인스턴스의 database 안 `orbital_auth` 에 있고 인증 역할만 읽고 씁니다. 토큰은 sha256 해시로만 둡니다.
  업무 역할은 뷰 `orbital.me`(자기 한 줄)를, `directory` 의 역할만 `orbital.users` 를 읽습니다.
  로그인 한 바퀴(`/_orbital/auth/…`): 링크 요청은 초대됐는지와 상관없이 같은 답(202 `{}`)이고, 같은 이메일로는 1분에 한 번만 링크를 만듭니다.
  링크는 15분, 한 번, 요청한 브라우저에서만 열리고, 세션 쿠키는 `HttpOnly; Secure; SameSite=Lax; Path=/` 입니다. 상태를 바꾸는 `POST` 는 `Origin` 이
  router 의 주소일 때만 받습니다. 로그인이 필요한 서비스는 세션 없이 화면을 열면 `login_path?next=…` 로, 화면이 아닌 요청은 401 로 답합니다.
  미리보기에는 씨앗 사용자(`db/seed/users.toml`)가 들어가고, 씨앗 사용자로 들어가는 길(`/_orbital/preview/sign-in`, CLI `orbital identity`)은 미리보기에만 있습니다.
  팩토리는 service key 로 운영에 사용자를 초대합니다(`POST /v1/instances/{id}/users`, SDK `users.invite`). 신원을 레이어 밖으로 내주는 길은 없습니다.
- **남은 일.** **실제 메일 발송기.** 지금 `orbitald` 는 개발용 메일함(`ORBITAL_HOME/outbox.jsonl`, 0600)에 쌓기만 합니다.
  관리 API 의 사용자 목록 · 역할 바꾸기 · 빼기(저장소 `AuthStore` 에는 있습니다). HTTPS 종단과 하위 도메인(지금은 `127.0.0.1:포트` 라 `__Host-` 쿠키를
  브라우저가 받는지는 재지 않았습니다). 신원에 업무 역할 싣기(`v2`)와 표마다의 역할 제한. OAuth 2.1. 세션 조회의 캐시(거둔 세션이 다음 요청부터 끊기는 규칙이 먼저입니다).
  링크 요청의 답은 같지만, 초대된 쪽이 DB 에 한 줄 더 쓰는 만큼의 시간 차는 재지 않았습니다.

## 예행연습과 되돌리기

- **되는 것.** 예행연습(`Admin::rehearse`): 운영 DB 를 복제한 사본에 마이그레이션을 돌리고 통과 여부 · 걸린 시간 · 멈춘 자리 · SQLSTATE · 표마다의 행 수만 돌려줍니다.
  사본은 만들자마자 아무도 접속하지 못하게 막고 끝나면 지웁니다. 되돌릴 지점(`mark` · `restore` · `forget`): 승격 직전의 DB 를 떠 두고, 돌아갈 때 이름을 바꿔 운영 자리에 놓습니다.
- **남은 일.** 복제하는 동안 proxy 가 요청을 붙잡기(지금은 운영 DB 의 문을 잠깐 닫고 붙어 있는 연결을 끊은 뒤 복제합니다. `quiesce` · `resume`). 잠금 시간 재기.
  XFS 에서의 복제 시간 재기. 앞의 코드와도 맞는 마이그레이션(열을 더하기만 하는 것)인지 가려 승인 카드에 적기.
- **결정.** [PostgreSQL 은 가장 높은 버전을 쓴다](decisions/2026-11-25-PostgreSQL-은-가장-높은-버전을-쓴다.md)

## 코드 저장

- **되는 것.** 인스턴스마다 레이어 안에 git 이력을 둡니다(`SourceStore`). 스캐폴드의 한 버전에서 갈라지고 그 기준점을 기억합니다.
  에이전트는 묶음(git bundle)으로 받아 가서 고친 뒤 묶음으로 올리고, `main` 의 이력을 잇는 묶음만 받습니다. 밖에서 온 객체는 받으면서 검사합니다.
  commit 하나에서 선언 · 권한 표 · 마이그레이션 · 씨앗 데이터를 읽어 검증하고(`assemble`), 인스턴스와 commit 에서 release 의 식별자를 짓습니다.
- **남은 일.** 바뀐 부분만 담은 묶음(지금은 통째로 오갑니다). 스캐폴드의 새 버전을 인스턴스에 합치는 길(업데이트).
- **결정.** [코드는 묶음으로 주고받고 미리보기는 따로 선 인스턴스다](decisions/2026-11-25-코드는-묶음으로-주고받고-미리보기는-따로-선-인스턴스다.md)

## 빌드와 미리보기

- **되는 것.** release 를 그 commit 에서 직접 빌드합니다. 에이전트가 올린 빌드 결과는 받지 않습니다. 미리보기(`Layer::preview`)는 뜻 없는 식별자로
  database 와 역할을 따로 세워 마이그레이션을 처음부터 돌리고, 씨앗 데이터를 넣고, 권한을 세워 권한 검사를 돌린 뒤 서버를 띄워 주소를 돌려줍니다.
  결과에는 어긋난 것, 운영과 견준 권한 변화의 문장, 승격을 막는 것이 함께 옵니다. 서버 서비스마다 proxy 가 하나 서고, 앱에는 그 주소와 레이어가 만든 비밀만 건넵니다.
  실행기는 갈아 끼우는 자리(`Runner`)이고 개발용 실행기(`LocalRunner`)가 있습니다. 환경을 비우고, 명령이 낳은 프로세스까지 한 묶음으로 멈춥니다.
- **남은 일.** 격리하는 실행기. 개발용 실행기는 이 기계의 프로세스로 돌리고 **격리하지 않습니다**(기획안 11절의 0번이 정합니다).
  밖에서 넣는 비밀을 미리보기와 운영에 잇기. 빌드의 캐시.

## 관리 서버와 CLI

- **되는 것.** 관리 서버(`orbitald`)의 HTTP API. 팩토리의 서버는 service key 로 스캐폴드를 올리고, 인스턴스를 세우고, 에이전트의 토큰을 받고, 승인받은 release 를 올립니다.
  에이전트는 토큰으로 코드를 받고 올리고, 미리보기를 세우고, 예행연습을 돌리고, 승격을 요청합니다. 운영을 바꾸는 길은 토큰 쪽에 없습니다.
  토큰은 서버가 서명하고(`token`), 범위는 core 가 판정합니다. 다른 인스턴스와 다른 팩토리의 것은 없는 것과 같은 답으로 돌려줍니다.
  운영에 올리기(`Layer::promote`): core 의 승격 규칙을 지난 뒤, 직전의 DB 를 되돌릴 지점으로 떠 두고, 마이그레이션을 돌리고, 권한을 세워 검사하고, 서버를 띄웁니다.
  중간에 깨지면 앞의 모습으로 돌립니다(운영에서만 뜨지 않는 서버를 올려, 앞의 release 와 앞의 DB 로 돌아가는 것을 쟀습니다).
  CLI 의 `clone` · `pull` · `push` · `preview` · `identity` · `rehearse` · `request-promotion` 이 이 API 를 부릅니다.
  팩토리의 서버는 SDK(`sdk/typescript`, `@harmony/orbital/server`)로 같은 API 를 부릅니다. 승인 화면에 세울 것(기다리는 release,
  권한이 어떻게 바뀌는지의 문장, 돌 마이그레이션)을 읽고, 사람이 승인하면 올립니다. SDK 의 테스트는 SDK 와 CLI 를 실제 관리 서버에 붙여 한 바퀴를 돕니다.
  앱에는 미리보기인지 운영인지를 `ORBITAL_STAGE` 로 알립니다.
- **남은 일.** 레이어의 기록을 DB 로 옮기기(지금은 파일 하나라 서버를 하나만 띄웁니다). 서버가 재시작됐을 때 운영의 서버를 다시 띄우기.
  새 서버를 먼저 띄우고 요청을 돌리기(지금은 승격하는 동안 운영이 내려갔다 뜹니다). 요청의 기록과 한도.
  기획안 9절의 SDK 모양 가운데 아직 없는 것: 인스턴스에 팩토리 쪽 식별자를 붙이기(`ref`), 토큰에 누구의 작업인지 적기(`actor`), `rollouts`.
- **결정.** [코드는 묶음으로 주고받고 미리보기는 따로 선 인스턴스다](decisions/2026-11-25-코드는-묶음으로-주고받고-미리보기는-따로-선-인스턴스다.md)

## 팩토리의 본보기

- **되는 것.** `examples/factory-todo` 가 팩토리 하나를 에이전트 플랫폼의 앱으로 세웁니다. service key 와 레이어의 주소는 팩토리 서버의 환경 변수에만 있고,
  고객은 앱에 연결한 계정(OAuth 의 주체)이며, 고객마다 인스턴스 하나를 스캐폴드 v1 에서 세워 그 짝을 팩토리의 파일에 둡니다.
  MCP 도구 넷: `workspace_open`(주소 · 인스턴스 · 두 시간짜리 `source · preview · rehearse` 토큰), `promotion_show`(승인 카드: 기다리는 release,
  권한이 바뀌는 문장, 실행될 마이그레이션), `promotion_approve`(화면 전용 `ui.visibility: ["app"]`, 카드가 보인 release 하나에만 묶인 한 번 쓰는 표),
  `production_status`. 스킬 `orbital-dev` 와 함께 훅 없는 ZIP 하나로 묶습니다(`src/pack.ts`). 테스트(`npm run test:factory`)는 실제 `orbitald` 와
  PostgreSQL 에 붙어 OAuth 로 연결하고 MCP client 와 `orbital` CLI 로 한 바퀴를 돌며, service key 가 답 · 로그 · 파일에 실리지 않는 것을 잽니다.
- **남은 일.** 하모니에 붙여 실물로 돌리기와 클로드에 올리기. 본보기의 로그인은 계정 이름을 적는 칸 하나라 실제 로그인으로 바꿔야 합니다.
  OAuth 의 토큰과 승인의 표는 팩토리 프로세스의 메모리에만 있습니다. 레이어의 토큰은 같은 초에 다시 내면 글자가 같고(일회값이 없음),
  승격에 실패해 되돌리거나 다시 올리면 운영의 주소(router 의 포트)가 바뀝니다(고정된 주소와 하위 도메인이 아직 없음).
