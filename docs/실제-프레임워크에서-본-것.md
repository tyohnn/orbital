# 실제 프레임워크에서 본 것

지금까지 레이어는 의존성이 없는 Node 서버(`node server.js`)로만 쟀습니다. 남의 팩토리가 쓰려면 `npm ci` 로 의존성을 받고 프레임워크로 빌드하는 앱이
서야 합니다. 그래서 두 본보기를 실제 앱으로 만들어 레이어에 세워 보고, 막힌 것 · 어색한 것 · 느린 것을 적었습니다(2026-11-25).

## 무엇을 세웠나

| 본보기 | 모양 | 버전(레지스트리에서 확인) |
|---|---|---|
| `examples/todo-next` | Next.js App Router 풀스택. 서버 서비스 하나. 로그인 화면(레이어의 이메일 링크), 자기 할 일만 보고 더하는 화면(서버 액션)과 JSON 길(`/api/todos`). `pg` 로 proxy 에 `member` 로 붙고 신원 머리말을 그대로 DB 에 넘긴다 | next 16.4.6, react 19.3.1, pg 8.23.1 |
| `examples/hr-nest-vite` | npm workspaces 하나에 NestJS API(`api`, `/api`, 업무 역할 셋)와 Vite 로 빌드한 정적 화면(`web`, `/`). 직원은 자기 급여 명세만, 팀장은 맡은 부서 사람의 것을, 급여 관리자는 전부를 본다 | @nestjs/* 12.6.2, @nestjs/cli 12.0.15, typescript 6.0.3, vite 8.3.8 |

둘 다 `package-lock.json` 을 commit 하고 빌드는 `npm ci` 로 시작합니다. 앱용 SDK(`@harmony/orbital/app`)는 npm 에 없어 스캐폴드처럼 `orbital-app.js` 를 넣어 두었습니다.
`hr-nest-vite` 의 권한 표는 팀장이 급여 명세를 「read own」(행 단위 규칙이 맡은 부서 사람의 것만 보인다)으로 바꿨습니다. 앞의 `none` 으로는 팀장이 팀원의 것을 볼 수 없습니다.

세우는 길은 실제 관리 서버의 HTTP 층 · 실제 PostgreSQL 19 · 레지스트리에서 받는 실제 `npm ci` 와 빌드 · 실제 앱 프로세스입니다(`crates/orbital-server/tests/frameworks.rs`).
작업을 열고 → git 으로 올리고 → 프리뷰(빌드 포함) → 씨앗 사용자로 들어가 자기 행만 보이는지 → 승격 요청 → 고객의 승인 → 운영에서 초대한 사람이 링크로 들어와 같은 것 →
쉬게 두어 재운 뒤 첫 요청에 깨는지 → 관리 서버를 다시 띄운 뒤까지 갑니다. `npm run test:frameworks` 로 부르고 `ORBITAL_PG` 가 없으면 건너뜁니다.

## 제안(짓지 않았다)

선언 파일의 모양을 바꾸는 것이라 사람에게 확인받은 뒤에 짓습니다.

1. **로그인 없이 내줄 경로.** 서비스에 `public = ["/_next/static/"]` 처럼 `auth = "required"` 에서도 들여보낼 경로의 머리를 적게 합니다.
   판정은 core 의 `admit` 이 하고, 이 경로에는 신원을 싣지 않습니다. 대신 레이어가 프레임워크의 이름을 알아 미리 넣는 길은 택하지 않습니다(레이어는 프레임워크를 모릅니다).
2. **정적 서비스의 되돌림.** 정적 서비스에 `fallback = "index.html"` 을 적으면, 파일이 없고 화면을 원하는 요청(`GET` + `Accept: text/html`)에만 그 파일을 내줍니다.
   스크립트 · 그림의 404 는 그대로 둡니다.
3. **저장소에서 한 번 도는 빌드.** 최상위에 `[build] command = "npm ci"` 를 두어 서비스의 빌드보다 먼저 한 번 돌게 합니다. 서비스의 `build` 는 그 뒤의 일만 적습니다.

## 바꾼 레이어의 동작

- `orbitald` 의 `ORBITAL_BUILD_ENV`: 빌드에만 건넬 환경 변수의 이름(쉼표로 가른다). 값은 `orbitald` 의 환경에서 읽는다.
- 빌드의 홈: `ORBITAL_HOME/caches/<인스턴스>`. 서버와 적합성 테스트는 앞처럼 빌드 폴더 안의 `.orbital-home` 을 쓴다.
- 프리뷰의 빌드는 레이어의 자물쇠 밖에서 돈다. 떠 있지 않은 release 의 빌드 폴더를 걷고, 인스턴스를 지우면 그 자리들을 걷는다. 로그에서 레이어의 폴더를 가린다.
