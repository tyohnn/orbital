# 실제 프레임워크에서 본 것

지금까지 레이어는 의존성이 없는 Node 서버(`node server.js`)로만 쟀습니다. 남의 팩토리가 쓰려면 `npm ci` 로 의존성을 받고 프레임워크로 빌드하는 앱이
서야 합니다. 그래서 두 본보기를 실제 앱으로 만들어 레이어에 세워 보고, 막힌 것 · 어색한 것 · 느린 것을 적었습니다(2026-11-25).

## 무엇을 세웠나

| 본보기 | 모양 | 버전(레지스트리에서 확인) |
|---|---|---|
| `examples/todo-next` | Next.js App Router 풀스택. 서버 서비스 하나. 로그인 화면(레이어의 이메일 링크), 자기 할 일만 보고 더하는 화면(서버 액션)과 JSON 길(`/api/todos`). `pg` 로 proxy 에 `member` 로 붙고 신원 머리말을 그대로 DB 에 넘긴다 | next 16.4.6, react 19.3.1, pg 8.23.1 |
| `examples/hr-nest-vite` | npm workspaces 하나에 NestJS API(`api`, `/api`, 업무 역할 셋)와 Vite 로 빌드한 정적 화면(`web`, `/`). 직원은 자기 급여 명세만, 팀장은 맡은 부서 사람의 것을, 급여 관리자는 전부를 본다 | @nestjs/* 12.6.2, @nestjs/cli 12.0.15, typescript 6.0.3, vite 8.3.8 |

둘 다 `package-lock.json` 을 commit 하고 의존성은 `npm ci` 로 받습니다(`todo-next` 는 서비스의 빌드에서, `hr-nest-vite` 는 저장소에서 한 번 도는 `[build]` 에서).
앱용 SDK(`@harmony/orbital/app`)는 npm 에 없어 스캐폴드처럼 `orbital-app.js` 를 넣어 두었습니다(`npm pack` 으로 묶어 새 폴더에 깔아 쓰는 것까지는 잽니다).
`hr-nest-vite` 의 권한 표는 팀장이 급여 명세를 「read own」(행 단위 규칙이 맡은 부서 사람의 것만 보인다)으로 바꿨습니다. 앞의 `none` 으로는 팀장이 팀원의 것을 볼 수 없습니다.

세우는 길은 실제 관리 서버의 HTTP 층 · 실제 PostgreSQL 19 · 레지스트리에서 받는 실제 `npm ci` 와 빌드 · 실제 앱 프로세스입니다(`crates/orbital-server/tests/frameworks.rs`).
작업을 열고 → git 으로 올리고 → 프리뷰(빌드 포함) → 씨앗 사용자로 들어가 자기 행만 보이는지 → 승격 요청 → 고객의 승인 → 운영에서 초대한 사람이 링크로 들어와 같은 것 →
쉬게 두어 재운 뒤 첫 요청에 깨는지 → 관리 서버를 다시 띄운 뒤까지 갑니다. 운영의 급여 일정을 그 시각에 부르는 것, 실제 브라우저(Playwright 의 Chromium)로
로그인 화면 · 세션 쿠키 · 화면 안의 경로를 여는 것, 큰 저장소를 git 으로 올리고 받는 것도 같은 묶음에 있습니다(`crates/orbital-server/tests/git.rs` 의 큰 저장소,
`tests/browser/*.cjs`). `npm run test:frameworks` 로 부르고 `ORBITAL_PG` 가 없으면 건너뜁니다. 브라우저가 없으면 브라우저의 테스트만 건너뛰고, CI 에서는 실패합니다.

## 실제 브라우저에서 본 것

- **Chromium 158 은 `http://127.0.0.1` 에서도 `__Host-orbital-session`(`Secure`)을 받고 다음 요청에 싣는다.** 127.0.0.1 을 믿을 만한 자리로 보기 때문이다.
  그래서 하위 도메인 없이 포트로 연 운영에서도 로그인 링크로 들어온 브라우저가 그대로 들어온다. 운영(HTTPS)에서는 원래 받는다.
  Firefox · Safari 와 `http://<하위 도메인>.localhost` 가 아닌 이름(예: `http://orbital.test`)에서는 받지 않을 수 있다(재지 않았다).
  Playwright 로 쿠키를 손으로 심을 때는 `url` 이 `http` 면 `Secure` 쿠키를 받지 않아 `domain` · `path` 로 심는다.
- 다른 주소(같은 `127.0.0.1` 의 다른 포트 = 같은 사이트, 다른 origin)의 화면이 보낸 로그아웃 폼과 링크 요청(fetch)은 `Origin` 검사로 403 이다.
  `SameSite=Lax` 는 같은 사이트라 이 경우를 막지 않는다. 막는 것은 `Origin` 이다.
- Next.js 의 로그인 화면은 로그인 없이 스크립트를 받아 hydrate 되고, 단추가 JS 로 링크를 요청한다(202, 폼이 GET 으로 나가지 않는다).

## 바꾼 레이어의 동작

- `orbitald` 의 `ORBITAL_BUILD_ENV`: 빌드에만 건넬 환경 변수의 이름(쉼표로 가른다). 값은 `orbitald` 의 환경에서 읽는다.
- `ORBITAL_SCHEDULE_TIMEOUT`: 일정으로 부른 요청을 기다리는 초(기본 600). `orbitald` 는 분이 바뀔 때마다 때가 된 일정을 부른다.
- 빌드의 홈: `ORBITAL_HOME/caches/<인스턴스>`. 서버와 적합성 테스트는 앞처럼 빌드 폴더 안의 `.orbital-home` 을 쓴다.
- 서버 서비스에 `HOST` 와 `HOSTNAME`(둘 다 `127.0.0.1`)을 건넨다.
- 프리뷰 · 승격 · 재시작의 빌드는 레이어의 자물쇠 밖에서 돈다. 떠 있지 않은 release 의 빌드 폴더를 걷고, 인스턴스를 지우면 그 자리들을 걷는다. 로그에서 레이어의 폴더를 가린다.
- 선언: 최상위 `[build] command`, 서비스의 `public` · `fallback`, 일정의 cron 식을 읽어 맞는 때가 오는지까지 본다(앞에서는 칸의 수만 셌다).
